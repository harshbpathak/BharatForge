# Contributing to BharatForge

Use Python 3.11+, create a virtual environment, and install `requirements.txt`. Run `streamlit run app.py` and select Try Demo before changing behavior. Run `python -m pytest -q` before opening a pull request.

Keep changes focused and explain the maintainer problem, resulting behavior, and validation in your PR. Update schemas, examples, and documentation when changing exported data. Report bugs with steps, expected/actual results, Python version, and redacted logs.

Never commit credentials, real private issue data, or `.env`. Mock all external API calls in automated tests. Preserve the BharatCode-only inference policy, read-only GitHub behavior, fixed HTTP destinations, explicit demo labels, strict output validation, and transparent heuristic score breakdowns.

Do not publish security-sensitive reports in public issues. Contact the repository owner privately through their GitHub profile for vulnerabilities, without including live credentials.

Contributions are provided under the repository's MIT license.
